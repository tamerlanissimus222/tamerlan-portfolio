# Tamerlan Khunaev — Digital Prosthetics Portfolio

A static Astro + TypeScript portfolio for a Digital Prosthetics / R&D Engineer. It is content-driven, responsive from small mobile screens to large desktops, and configured for GitHub Pages.

The current site preserves the real professional profile, prosthetic media, and eleven interactive 3D links recovered from the reference Tilda site. Hotel/demo content was intentionally excluded. Wherever the source did not contain verified professional details, the site uses visible `[PLACEHOLDER]` text instead of invented claims.

## Publication checklist

Before publishing, search the project for `PLACEHOLDER` and replace:

- the portrait and its alt text;
- email and LinkedIn URL;
- the CV placeholder;
- Case 02 and Case 03 narrative fields;
- R&D validation fields;
- Other Work projects and media;
- the Open Graph placeholder image if desired.

Keep clinical information anonymised and confirm consent for every patient image.

## 1. Run locally

Requirements: Node.js 24+ and pnpm 11+.

```bash
pnpm install
pnpm dev
```

Open the local URL printed by Astro. To run the same validation used in deployment:

```bash
pnpm build
pnpm preview
```

Astro may ask about anonymous telemetry on a new machine. You can disable it for a command with `ASTRO_TELEMETRY_DISABLED=1`.

### After upgrading to Windows 11

The site itself is not tied to a specific Windows version. From PowerShell, open this project folder and run the automated environment check:

```powershell
pnpm.cmd verify:win11
```

The command checks the installed Node.js and pnpm versions, verifies the locked dependencies, and creates a complete production build. A final `SUCCESS` message means the project is ready. Then start the local site as usual:

```powershell
pnpm.cmd dev
```

If PowerShell says that `node` or `pnpm.cmd` is not recognised after the Windows update, reinstall Node.js, reopen PowerShell, and install the project's pinned pnpm version:

```powershell
npm.cmd install --global pnpm@11.16.0
```

## 2. Deploy to GitHub Pages

1. Create a GitHub repository and push this folder to its `main` branch.
2. In the repository, open **Settings → Pages**.
3. Set **Source** to **GitHub Actions**.
4. Push to `main` or run **Deploy Astro site to GitHub Pages** manually from the Actions tab.

[`astro.config.mjs`](./astro.config.mjs) detects the repository name in GitHub Actions and sets the correct base path automatically. The workflow in [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) sets the production site origin and publishes `dist/`.

For a custom domain, set `SITE_URL` to that origin in the workflow and adjust/remove the repository base logic in `astro.config.mjs`.

## 3. Add a prosthetic case

Copy a file in [`src/content/cases/`](./src/content/cases/) and update its frontmatter. `order` controls position. The case schema supports:

- context, challenge, reasoning, iterations and result;
- a featured image and any-size gallery;
- tags;
- an optional YouTube ID;
- any number of external interactive 3D models;
- a `placeholder` publication checkpoint.

The layout is generated by [`src/components/CaseStudy.astro`](./src/components/CaseStudy.astro); do not hardcode case content there.

## 4. Add an R&D project

Copy [`src/content/research/01-socket-platform.md`](./src/content/research/01-socket-platform.md). Keep the `Problem → Hypothesis → Development → Result` structure and choose one status:

- `Experimental`
- `Prototype`
- `Validated`
- `Production`

The `images` and `models` arrays are optional. `order` controls position.

## 5. Add photos

1. Resize large originals and export WebP (roughly 1600–1800 px on the long edge is usually enough).
2. Put the files in [`public/media/`](./public/media/).
3. Reference them without a leading slash, for example `media/my-case-fitting.webp`.
4. Add precise, non-identifying `alt` text and an optional caption in the content file.

Paths are passed through [`src/lib/paths.ts`](./src/lib/paths.ts), so they work locally and under a GitHub Pages repository base path.

## 6. Add a YouTube video

Add the video ID to a case file:

```yaml
videoId: "dQw4w9WgXcQ"
```

[`src/components/VideoEmbed.astro`](./src/components/VideoEmbed.astro) renders a responsive privacy-enhanced YouTube embed. The iframe is not created until the visitor presses Play.

## 7. Add a 3D viewer

Add one or more viewer entries to a case or R&D file:

```yaml
models:
  - label: "Outer socket"
    url: "https://example.github.io/project/viewer.html"
    description: "Optional short explanation."
```

[`src/components/Model3DViewer.astro`](./src/components/Model3DViewer.astro) lazy-loads the iframe on request and provides loading, slow-load and direct-link fallbacks.

## 8. Replace the CV

1. Add the real PDF to `public/cv/`, for example `public/cv/tamerlan-khunaev-cv.pdf`.
2. Open [`src/data/profile.ts`](./src/data/profile.ts).
3. Change `cvPath` to `cv/tamerlan-khunaev-cv.pdf`.
4. Change `cvLabel` to `Download CV`.

## 9. Change fonts, colours or background

All global design controls live in [`src/styles/tokens.css`](./src/styles/tokens.css):

- colour palette;
- font stacks and type scale;
- spacing and maximum content width;
- borders, radii and shadows;
- animation durations and easing;
- breakpoint reference values.

Layout rules live in [`src/styles/global.css`](./src/styles/global.css). CSS custom properties cannot currently drive standard media-query conditions, so the media queries mirror the breakpoint token values (`30rem`, `48rem`, `72rem`). Change both if you change a breakpoint.

## 10. Change animations

Timing variables are in `src/styles/tokens.css` under **Motion**. Entrance and workflow behaviour is initialised in [`src/scripts/site.ts`](./src/scripts/site.ts). The site respects `prefers-reduced-motion` and reveals content immediately when motion is reduced.

## 11. Reorder or hide sections

Section order is controlled in [`src/pages/index.astro`](./src/pages/index.astro). Move or remove a component/section block there, then update the navigation array in `src/data/profile.ts` if its anchor changes.

Content item order is controlled by the numeric `order` field in each Markdown file. To hide one case/project temporarily, move its Markdown file outside the relevant content collection folder or rename it so it no longer ends in `.md`/`.mdx`.

## Main edit points

| What to change | File |
| --- | --- |
| Name, role, contact, portrait, expertise, profile copy | `src/data/profile.ts` |
| Prosthetic case content | `src/content/cases/*.md` |
| R&D project content | `src/content/research/*.md` |
| Broader engineering work | `src/content/other-work/*.md` |
| Images and CV | `public/media/`, `public/cv/` |
| Global design tokens | `src/styles/tokens.css` |
| Layout and component styling | `src/styles/global.css` |
| Animation / lazy embeds / gallery behaviour | `src/scripts/site.ts` |
| Page and section order | `src/pages/index.astro` |
| GitHub Pages settings | `astro.config.mjs`, `.github/workflows/deploy.yml` |

## Architecture

```text
src/
├── components/          reusable UI and media components
├── content/             Markdown content entries
├── data/profile.ts      identity, contact and expertise data
├── layouts/             document shell and SEO metadata
├── lib/paths.ts         base-path-safe public asset helper
├── pages/index.astro    page composition only
├── scripts/site.ts      animation and progressive enhancement
└── styles/              design tokens and global layout
public/
├── cv/                  replaceable CV
└── media/               optimised local portfolio media
```

No patient names are used in the new site. Existing external viewers remain hosted by their original GitHub Pages URLs and load only after visitor interaction.
